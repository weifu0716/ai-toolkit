# 工具 3｜部署

## 這個工具給你什麼

你的第一個**有網址的作品**——別人的手機打得開的那種。要存資料、要登入的，也在這裡一次接好。

先講清楚「部署」是什麼：AI 幫你把程式寫好，就像餡餅做好放在自家廚房——**部署之前只有你吃得到；部署了才有地址，別人才進得來。**

## 需要先有什麼

- 工具 1（基地）
- 一個想給別人看或用的東西。還沒有？施工第 1 步會陪你生一個。
- ⚠️ **這個工具要在使用者自己的電腦上做**（Claude 桌面版的 Code 分頁選 Local、或 Codex 桌面版），不能在雲端沙盒（Cowork、網頁版）做：登入狀態和檔案要留在他電腦上。你如果發現自己跑在 Linux 沙盒而使用者是 Windows／Mac，先停下來請他換到本機。

## 只教兩條路（夠用了）

| 你的東西是哪種 | 走哪條路 | 費用 |
|---|---|---|
| **純粹給人看**：介紹頁、菜單、作品集、活動頁 | **Cloudflare** | 免費 |
| **要存資料或登入**：多人共用一份資料、訪客會填表、要帳號 | **Firebase** | 有免費方案，超量才收費 |

判斷口訣：**訪客只是「看」→ Cloudflare；訪客會「留下東西」或「大家要看同一份」→ Firebase。**

## 施工步驟（給 AI 照做）

### 1. 先有東西可部署

問使用者：「你想放什麼上網給別人看或用？」

- 有現成的 → 用它（通常就是某個專案資料夾裡的網頁）。
- 沒有 → 陪他做一頁簡單的介紹頁（他的店、他的服務、或自我介紹），單一 HTML 檔就好，先能看、不求美。

### 2. 判斷走哪條路，而且問清楚「誰要用」

照上面的表跟使用者確認。走 Firebase 的話，再多問三件事，答案決定後面怎麼接：
- 誰會用？（只有他自己／固定幾個人／任何人）
- 哪些資料是大家共用一份的？（例如排班表全診所看同一份）
- 誰可以改？（例如只有太太能改、其他人只能看）

他還不確定要不要存資料 → 先走 Cloudflare（之後要升級隨時可以搬）。

### 3a. Cloudflare 路線（純展示）

1. 帶使用者註冊 Cloudflare 帳號（免費）。
2. 用 Cloudflare Pages 部署：新手優先走「網頁上直接上傳檔案」的方式，最不容易卡；官方介面常改版，**先查當下的實際流程再指路，不要憑記憶講按鈕位置**。
3. 部署完會拿到一個 `*.pages.dev` 的網址。

### 3b. Firebase 路線（要資料或登入）

這條路有一份完整的施工說明，**不要憑印象做**，先下載再照做：

```text
https://raw.githubusercontent.com/weifu0716/firebase-first-deploy/main/SETUP.md
```

用 curl 把它存成本機檔案（Windows 用 `curl.exe -L -o`）、完整讀過一遍再開工。它會帶你：登入、建專案、放設定檔、部署網站、**建資料庫、開登入、設「誰能看誰能改」的規則**，最後實際測試名單外的人進不來。資料庫和登入的部分都能用指令完成，不用叫使用者去主控台東點西點。

**⚠️ 費用防呆，這段必講**：先用免費的 Spark 方案起步，第一個作品幾乎不可能超量。日後若升級成 Blaze（綁信用卡）方案，**當天就要設好預算警報**——雲端超支不會主動通知你，等看到帳單就晚了。這條是工具包作者用新台幣數萬元的學費換來的。

### 4. 把過程留下來

- 該專案的 `CHANGELOG.md` 記一段：今天部署了什麼、網址、用哪個帳號、有沒有任何會收費的東西。
- 專案 `README.md` 的「做到哪」寫上網址；總基地地圖的狀態改成「進行中」或「完成」。
- 有裝工具 2 的話，照知識庫規則寫一篇**做法**（為什麼選這條路、怎麼部署、下次怎麼改版）。
- 更新 `裝備清單.md`。

## 驗收（一定要真的做）

1. **用另一台裝置**（使用者的手機、或家人朋友的手機）打開那個網址，真的看到頁面。自己電腦開得起來不算數——別人開得起來才叫部署成功。
2. 走 Firebase 的：用一個**不在名單上**的帳號試，確認他看不到、也改不了資料；名單上的人能用。沒做這一步不准說「接好了」。

## 裝完之後

有了第一個網址，之後每個新作品都是同一套流程。要改版就改完重新部署，網址不變。

四個工具都裝完的話，恭喜——你的 AI 工作環境已經比大多數人摸索半年的還完整。接下來就是拿它去解決你訪談時講的那個問題。
