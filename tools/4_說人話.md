# 工具 4｜說人話（去 AI 味）

## 這個工具給你什麼

一個**會幫你把 AI 腔改掉的校稿員**。裝完之後，你寫好（或叫 AI 寫好）一段要給別人看的文字——貼文、LINE 公告、Email、簡報、活動文案——說一句「幫這段說人話」，它就會：

- 抓出讀起來像 AI 寫的地方：空話套話（「賦能」「打造全新體驗」）、「不僅⋯⋯更⋯⋯」這類公式句、每段都要總結一次、破折號太多
- 順手校正中國用語和半形標點（「運營」改「營運」、半形逗號改全形）
- **先列一張清單給你勾**：每一條寫原句、為什麼要改、建議怎麼改。你說要改哪幾條，它才動筆
- 價格、日期、人名、連結這些一個字都不動；它不知道的事實不會自己編，會標「（需作者補充）」

這個工具不是這份工具包作者寫的，是**雷蒙三十**開源的 [speak-human-tw](https://github.com/Raymondhou0917/speak-human-tw)（MIT 授權，免費）。這裡做的事是：幫你裝好、接進家規、教你什麼時候用、什麼時候別用。

## 需要先有什麼

- 工具 1（基地）：要有家規，才能把「對外文字先過一次」寫進去
- 不用等工具 2、3，裝完基地隨時可以裝

## 施工步驟（給 AI 照做）

### 1. 先跟使用者講兩句

用白話講，不要上課：

- 「我要幫你裝一個校稿工具，專門把 AI 腔改掉，是別人開源的、免費。」
- 「它的習慣是先列清單問你要改哪幾條，不會直接改你的稿。想省事就跟它說『直接改』。」

### 2. 裝進電腦

裝在使用者的**個人 skills 資料夾**，不放家資料夾裡。原因：skill 要裝在這裡，不管他從哪個資料夾開對話都叫得到；以後也只要更新這一份。

位置：Mac 是 `~/.claude/skills/speak-human-tw/`，Windows 是 `C:\Users\<名字>\.claude\skills\speak-human-tw\`。

先跑 `git --version` 看有沒有 Git（工具 1 裝過就有），再用對應的指令。要寫入家資料夾以外的地方，畫面會問允不允許，先跟他講一聲。

**有 Git（推薦，以後一行就能更新）**：

```text
Mac：
git clone https://github.com/Raymondhou0917/speak-human-tw.git ~/.claude/skills/speak-human-tw

Windows（PowerShell）：
git clone https://github.com/Raymondhou0917/speak-human-tw.git "$HOME\.claude\skills\speak-human-tw"
```

**沒有 Git**：一行一個指令，把這 7 個檔抓下來（Windows 把 `curl` 換成 `curl.exe`，`~` 換成 `$HOME`）。注意這個 repo 的主分支叫 `master`，不是 `main`：

```text
curl -fsSL --create-dirs -o ~/.claude/skills/speak-human-tw/SKILL.md https://raw.githubusercontent.com/Raymondhou0917/speak-human-tw/master/SKILL.md
curl -fsSL --create-dirs -o ~/.claude/skills/speak-human-tw/references/patterns.md https://raw.githubusercontent.com/Raymondhou0917/speak-human-tw/master/references/patterns.md
curl -fsSL --create-dirs -o ~/.claude/skills/speak-human-tw/references/humanize.md https://raw.githubusercontent.com/Raymondhou0917/speak-human-tw/master/references/humanize.md
curl -fsSL --create-dirs -o ~/.claude/skills/speak-human-tw/references/protected-list.md https://raw.githubusercontent.com/Raymondhou0917/speak-human-tw/master/references/protected-list.md
curl -fsSL --create-dirs -o ~/.claude/skills/speak-human-tw/references/scenes.md https://raw.githubusercontent.com/Raymondhou0917/speak-human-tw/master/references/scenes.md
curl -fsSL --create-dirs -o ~/.claude/skills/speak-human-tw/references/taiwan-localization.md https://raw.githubusercontent.com/Raymondhou0917/speak-human-tw/master/references/taiwan-localization.md
curl -fsSL --create-dirs -o ~/.claude/skills/speak-human-tw/references/examples.md https://raw.githubusercontent.com/Raymondhou0917/speak-human-tw/master/references/examples.md
```

裝完自己確認：`SKILL.md` 在、`references/` 裡有 6 個檔、打開看中文正常（不是亂碼、不是 404 頁面）。

> 用 Codex 的人也裝在同一個位置。Codex 不一定會自動找到這裡，所以下一步的家規會直接寫出檔案路徑，兩邊都讀得到同一份。

### 3. 接進家規

在 `CLAUDE.md` 和 `AGENTS.md` **都**加這一段（兩份保持一樣）。`<路徑>` 換成上一步實際裝好的完整路徑，例如 `C:\Users\Amy\.claude\skills\speak-human-tw\SKILL.md`：

```markdown
## 寫給別人看的文字
- 要給別人看的文字（貼文、LINE 訊息、公告、Email、簡報、文案），稿寫好後，
  先照「說人話」skill 檢查一次 AI 味再交給我。規則在：<路徑>
- 它會先列建議清單讓我勾；我說「直接改」才可以跳過清單、改完再給我看改了哪些。
- 論文、研究報告、正式公文：只標問題、不幫我改寫，而且保留正式語氣（不加口語、不加故事）。
- 程式碼、紀錄檔、設定檔不用套。
```

### 4. 留紀錄

- 工作台 `CHANGELOG.md` 加一段：今天裝了說人話、裝在哪、用 Git 還是 curl 裝的。
- `裝備清單.md` 把「4 說人話」打勾、寫日期；這一行如果還沒有，就補上。
- Git 存一版：「裝說人話」。

## 論文、報告可以用嗎？

**可以用一半。** 這個工具做兩件事：一是**抓 AI 痕跡**，二是**把文字改得有人味**。論文只適合用第一件。

| 它會做的事 | 用在論文 |
|---|---|
| 抓空話：「具有重要意義」「提供寶貴參考」「隨著科技快速發展」 | ✅ 很適合，口試委員最討厭這種句子 |
| 抓對仗排比、價值上升詞、破折號太多 | ✅ 適合 |
| 校正中國用語、半形標點 | ✅ 很適合 |
| 不知道的事實標「需作者補充」、不亂編 | ✅ 適合，也避免假引用 |
| 加口語、語氣詞、個人故事、允許岔題、允許不收尾 | ❌ 不適合，論文要的是書面語和完整結論 |
| 把「可能」「本研究推測」這類保守說法刪掉 | ❌ 不適合，論文的保守說法是精準，不是 AI 味 |
| 嫌「首先、其次、最後」太公式 | ⚠️ 看情況，研究步驟照順序寫是正常的 |

**論文的用法：讓它只標、你自己改。** 句子是你自己改的，才是你的論文；學校對 AI 改寫可能也有規定，先查清楚。直接貼這段給 AI，再附上要檢查的段落：

```text
這是我的論文（或研究報告）的一段。用「說人話」skill 的 annotation mode，只標問題、不要改寫。
照學術寫作的標準判斷：保留書面語、必要的限定詞（可能、本研究推測）、章節結構和結論段；
不要建議加口語、個人故事或岔題；引用、數據、統計值、專有名詞、量表名稱一個字都不能動。
重點幫我抓：空話套話、對仗排比、中國用語、半形標點。
```

## 驗收（一定要真的做）

請使用者**開一個新對話**，貼這段（故意寫得很 AI），說「幫這段說人話」：

```text
在當今瞬息萬變的時代，我們的團隊不僅致力於提升服務品質，更全面賦能每一位夥伴，打造全新的顧客體驗。透過精細化運營,我們相信每一次的用心,都將為您帶來前所未有的感動。總的來說，選擇我們，就是選擇美好的未來！
```

過關要看到三件事：

1. AI 沒有直接丟一篇改好的，而是先列**編號清單**（原句／為什麼／建議），最後問要改哪幾條
2. 清單裡有抓到「運營」要改「營運」、半形逗號要改全形
3. 回它「全部照改」，拿到改寫版；改寫版沒有自己多編出原文沒有的事實（例如憑空多出一個數字或店名），編不出來的地方有標「（需作者補充）」

在 Codex 測，如果它沒反應，直接說「照家規裡說人話的規則檢查這段」；還是不行，檢查家規裡的路徑對不對。

三件都過 → 裝好了。

## 裝完之後

- 平常不用記指令，說「說人話」「去 AI 味」「這段好 AI」都會叫得到它；家規也會讓 AI 交對外文字之前自己先過一次。
- 只想看哪裡有問題、不想被改：說「先標問題不要改」。
- **更新**：用 Git 裝的，請 AI 到 skill 資料夾跑 `git pull`；用 curl 裝的，照第 2 步重抓一次。

驗收通過後，跟使用者說：「工具 4 裝好了。還有沒裝的工具嗎？沒有的話今天就到這裡。」
